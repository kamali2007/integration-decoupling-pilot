# Canonical Event Contract Specification

## 1. Scope & Objective
This specification defines the formal schema, constraints, and semantics of the **Canonical Event Layer**. The canonical event layer represents domain-level business facts, entirely decoupled from the idiosyncratic wire formats of downstream suppliers.

## 4. Idempotency & Deduplication Semantics

1. Every incoming order is assigned an `idempotency_key`, defaulting to `IDEMP-ORD-{order_id}` unless explicitly supplied in client headers.
2. The Gateway executes an atomic lookup on `CanonicalEvent.idempotency_key`.
3. If an existing record matches:
   - The transaction is not re-dispatched to supplier adapters.
   - An audit record `DUPLICATE_DETECTED` is recorded.
   - The status returned is `DUPLICATE_IGNORED`.
   - Idempotency guarantees prevent redundant financial and manufacturing commitments.
